## Included scope

- Project-first Dashboard;
- release/local/runtime Project Registry layering;
- Planner Resource Selection;
- read-only Project Context Snapshot;
- Dashboard Settings with immutable code-owned limits;
- automatic Node test discovery;
- clean onboarding validation.

This release does not change the Task Runtime state machine, Workflow Runtime semantics, Harness audit contract, approval boundary, side-effect guard, or existing MCP tool semantics.

## Supported environment

- Windows PowerShell;
- Node.js 20 or newer with npm;
- Claude Code CLI configured for a compatible provider;
- loopback local Bridge and dependency-free Dashboard;
- OpenAI `tunnel-client` for supported ChatGPT custom-MCP access.

ChatGPT plan, developer-mode, custom-app, write-action, Platform Tunnel, and workspace-association availability are controlled by OpenAI and can change independently of this repository. At the time of this release candidate, OpenAI documents full MCP write actions for supported Business and Enterprise/Edu workspaces. Confirm current availability in the official documentation before onboarding.


### GPT Web validation debt

- Supervisor Review completed in ChatGPT Web; explicit Review Result persistence was not exercised.
- Memory application occurred before the final GPT review during dogfood; this is not the recommended production sequence.
- The Memory application required explicit human confirmation. No approval boundary was bypassed and Project Memory was not updated automatically.
- The recommended production order remains: Review → save review → confirm Memory apply.

## Known limitations

- Windows is the primary validated platform.
- Execution stages are sequential; there is no parallel Agent execution.
- The Dashboard uses polling and has no notification service.
- Approval names are local audit metadata, not authenticated identities.
- Runtime and evidence persistence are file-backed, not tamper-proof.
- Provider cost summaries may differ from upstream billing.
- The local Bridge must remain on loopback; ChatGPT access depends on a correctly configured Secure MCP Tunnel.
- ChatGPT custom-MCP and write-action availability depends on account, workspace, admin, and Platform Tunnel permissions.
- Worker ownership observability and automatic process recovery are not part of this release.
- One transient Windows file-lock/timing failure was observed during repeated local Workflow Runtime testing; the isolated clean clone and final full 30/30 test gates passed.
